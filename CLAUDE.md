## Project Overview

Static site that publishes GoalPlate's legal pages at `https://goalplate.app`: Privacy Policy, Terms of Service (English controlling + Spanish courtesy translations) and the account-deletion instructions page. Markdown under `src/` → HTML via `build.js` (`marked`) → `dist/`, deployed by Azure Static Web Apps on every push to `main`. See `README.md` for the build, routes and the consent-version bump rule.

The app repo is `../goal-plate-ia-project`; its `docs/` folder (start with `docs/handoff.md`) is the source of product context, and `docs/privacy-policy.md` / `docs/terms-of-service.md` there are the historical seeds of `src/privacy/index.md` / `src/terms/index.md` here — keep them in sync when the published text changes.

## Important Rules

- **Branch per change, PR to `main`**: `main` auto-deploys to production, so never commit to it directly. Every fix/feature goes on its own branch off `main` (`feat/<slug>`, `fix/<slug>`, `content/<slug>` for legal-text edits) and lands via a PR. The Azure workflow builds a **preview environment for every PR** — open the preview URL and read the changed page before merging. After merge, delete the branch.
- **Model roles per stage — Fable plans, Opus executes, Fable reviews**: same three hand-offs as the app repo. (1) **Plan** in the main session (Fable, the default model) in Plan Mode for anything beyond a one-file edit. (2) **Execute** by spawning the `implementer` agent (`~/.claude/agents/implementer.md`, Opus) with the approved plan text and this repo's path; it never commits. (3) **Review** by spawning the `reviewer` agent (`~/.claude/agents/reviewer.md`, Fable, read-only, fresh context) before any commit; resolve every blocking finding first. Skip the hand-offs for trivial one-file edits. Manual fallback: `/model opus` after the plan is approved, `/model fable` before committing.
- **Verify the build before committing**: `npm run build` must succeed and every route in `build.js` must render; open the affected `dist/**/index.html` locally. A new page needs three things together: a `routes` entry in `build.js`, a rewrite in `staticwebapp.config.json`, and a link from `src/index.md`.
- **Language parity**: any change to `src/privacy/index.md` or `src/terms/index.md` must be mirrored in the matching `es.md` (and any future locale) in the same PR, keeping the "English controls" notice at the top of each translation. The English version is the legally controlling text.
- **Material legal changes bump the consent version**: if the meaning of the Privacy Policy or Terms changes, update the `Last updated` line and version header in the markdown **and** bump `CURRENT_CONSENT_VERSION` in the app repo (`backend/data/consent_store.py` and `GoalPlate/src/context/ConsentContext.tsx`) so existing users re-consent. Typo fixes do not bump.
- **Commits**: Conventional Commits (`feat`, `fix`, `docs`, `content`, `chore`, `ci`), imperative, lowercase description; stage explicit paths, never `git add -A`; end with the `Co-Authored-By` / `Claude-Session` trailers the harness names for the session.
- **Nothing sensitive here**: this repo is public. No keys, tokens, or personal data beyond the operator contact details already published.
